# Gleiswerk v0.0.10

## New capability

Gleiswerk v0.0.10 adds a firmware-pinned, supervised CS3+ capture adapter to
`gleiswerk commissioning capture`. It collects the controller's configured
command and S88 feedback mappings plus current S88 states, then produces the
complete capture consumed by `gleiswerk commissioning verify`. The adapter
fails closed for an unknown firmware, changed response shape, incomplete
configuration, duplicate addresses, or incomplete S88 state.

## Configuration contract

Schema-v3 topology vocabulary and the Installation Binding are unchanged. A
capture now records the characterized CS3+ acquisition method, its version,
and a canonical configuration-snapshot hash alongside the commissioned
firmware, endpoint, command-channel, feedback-channel, and occupancy-state
data. See the [hardware commissioning workflow](https://micknudsen.github.io/gleiswerk/commissioning-cli-workflow/) and [schema-v3 topology contract](https://micknudsen.github.io/gleiswerk/schema-v3-topology-contract/).

## Non-goals

This release does not implement a live-hardware command path, command
turnouts, clear signals, dispatch trains, or create movement authority from
live hardware. The adapter makes only characterized read requests during a
supervised commissioning capture; it does not establish physical turnout
position or add support for other controllers, Link S88, feedback families, or
untested CS3 firmware.
