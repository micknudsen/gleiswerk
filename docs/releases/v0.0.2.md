# Gleiswerk v0.0.2

## New capability

Gleiswerk v0.0.2 adds a versioned, validated layout-configuration boundary.
Use `gleiswerk layout validate path/to/layout.toml` to validate a layout before
other Gleiswerk commands consume it. Python callers can load the same contract
through `gleiswerk.layout_config.load_layout`.

## Configuration contract

Schema version 1 describes named blocks, turnouts, and directional routes in a
UTF-8 TOML file. It validates the allowed vocabulary, identifiers, turnout
positions, ordered route blocks, and cross-references. Diagnostics are stable,
ordered, and include a code and configuration path. The shipped
`examples/reference-layout.toml` exercises the complete version-1 vocabulary.

See the [layout configuration documentation](https://micknudsen.github.io/gleiswerk/layout-configuration/)
for the full contract and examples.

## Non-goals

This release does not introduce controller addresses, occupancy detection,
physical topology validation, route-conflict checking, turnout commands,
signals, train movement, dispatching, simulator behavior, or hardware control.
Configuration describes a layout; it does not authorize or perform operations.
