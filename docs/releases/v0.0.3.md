# Gleiswerk v0.0.3

## New capability

Gleiswerk v0.0.3 adds conservative route-conflict analysis for validated
layouts. Use `gleiswerk layout conflicts path/to/layout.toml` to identify route
pairs that share blocks or require incompatible positions of the same turnout.
For layouts with no identified conflicts, it reports that result explicitly;
otherwise it lists each conflict with its reason.

## Configuration contract

This release does not change the version-1 layout configuration vocabulary or
validation compatibility. The analysis reads the existing named blocks,
turnouts, and directional routes after validation. See the [layout
configuration documentation](https://micknudsen.github.io/gleiswerk/layout-configuration/)
for the complete contract and analysis semantics.

## Non-goals

This release does not introduce occupancy detection, physical topology
validation, reservations, controller addresses, turnout or signal commands,
movement authorization, train movement, dispatching, simulator behavior, or
hardware control. Route-conflict analysis is an advisory safety aid; it does
not authorize or perform operations.
