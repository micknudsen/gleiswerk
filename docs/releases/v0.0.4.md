# Gleiswerk v0.0.4

## New capability

Gleiswerk v0.0.4 adds validated logical topology configuration. A layout can
now declare blocks and their endpoints, directed traversals, turnout
conditions, and routes assembled from continuous traversals. Use `gleiswerk
layout validate path/to/layout.toml` to check a topology declaration before
using it.

## Configuration contract

Layouts use schema version 2. The required `traversals` table defines directed
endpoint-to-endpoint passages; optional `blocks`, `turnouts`, and `routes`
tables provide the objects they reference. Routes contain ordered traversal IDs
and must be continuous, while their turnout requirements are derived from the
traversals. Schema version 1 layout files are not supported. See the [layout
configuration documentation](https://micknudsen.github.io/gleiswerk/layout-configuration/)
for the complete vocabulary, validation rules, and diagnostics.

## Non-goals

This release does not introduce geometry, controller addresses, occupancy
detection, reservations, turnout or signal commands, movement authorization,
train movement, dispatching, simulator behavior, or hardware control. A valid
topology remains descriptive only: it neither reserves railway resources nor
permits a train to move.
