# Gleiswerk v0.0.5

## New capability

Gleiswerk v0.0.5 adds validated, resource-complete logical topology and
compiled RoutePlans. Layout authors can describe Track Sections, Connections,
Junction Passages, Occupancy Zones, Protection Zones, and Protection Rules,
then compile a uniquely determined route into its resource claims and Control
Device requirements.

## Configuration contract

Layouts use schema version 3 in UTF-8 YAML files with a `.yaml` suffix. The
reader accepts no earlier schema, so schema-version-1 and schema-version-2
layouts must be re-authored against the schema-v3 model; they are historical
records, not migration sources. See the [layout configuration guide](https://micknudsen.github.io/gleiswerk/layout-configuration/)
and [schema-v3 topology contract](https://micknudsen.github.io/gleiswerk/schema-v3-topology-contract/)
for the complete vocabulary, validation, compiler behavior, and diagnostics.

## Non-goals

This release does not introduce controller addresses or Installation Bindings,
occupancy-feedback adapters, resource reservation, Control Device commands,
signals, movement authority, dispatching, simulator operation, or hardware
control. A valid layout and compiled RoutePlan remain descriptive safety inputs;
they neither reserve resources nor permit a train to move.
