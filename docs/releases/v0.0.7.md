# Gleiswerk v0.0.7

## New capability

Gleiswerk v0.0.7 adds controller-independent, in-memory RoutePlan
reservations. The core atomically acquires and releases complete route-plan
claims, rejects conflicts with deterministic explanations, and requires the
same opaque owner identity to release a reservation. The bounded
`gleiswerk layout reservations` command evaluates a finite YAML operation
sequence and reports its results deterministically.

## Configuration contract

Reservations use compiled RoutePlans from a validated schema-v3 topology and
do not add or change layout configuration vocabulary. The operations document
accepted by the command is documented in the [reservation CLI
workflow](https://micknudsen.github.io/gleiswerk/reservation-cli-workflow/).
See the [route reservation
contract](https://micknudsen.github.io/gleiswerk/route-reservation-contract/)
for core results, ownership, conflict explanations, and lifecycle semantics.

## Non-goals

This release does not persist reservations, coordinate reservations between
processes, command Control Devices, observe occupancy or device feedback,
clear signals, establish movement authority, dispatch trains, operate the
simulator, or control hardware. An acquired reservation is not evidence that a
device moved or permission for a train to move.
