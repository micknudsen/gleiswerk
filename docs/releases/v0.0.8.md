# Gleiswerk v0.0.8

## New capability

Gleiswerk v0.0.8 adds controller-independent, in-memory movement-authority
evaluation to the reservation workflow. It grants an opaque, time-bounded
authority only for a live, owner-matched reservation whose complete route scope
is supported by fresh, validated logical occupancy and Control Device position
evidence. A later reevaluation revokes the authority on the first failed
prerequisite or at expiration, while retaining the separate reservation.

The bounded `gleiswerk layout reservations` command evaluates a finite YAML
workflow of reservations, logical evidence, and authorities with deterministic
reports and a simulated monotonic clock.

## Configuration contract

This release does not add or change schema-v3 layout vocabulary. Authority
workflows use an operations document with explicit evidence freshness and
maximum-validity settings; see the [reservation and movement-authority CLI
workflow](https://micknudsen.github.io/gleiswerk/reservation-cli-workflow/) and
[movement-authority contract](https://micknudsen.github.io/gleiswerk/movement-authority-contract/)
for the complete workflow, ordered failure explanations, and safety boundary.

## Non-goals

This release does not persist or coordinate reservations or authorities,
connect to real evidence sources, command Control Devices, observe real
feedback or occupancy, clear signals, dispatch trains, operate the simulator,
or control hardware. An authority is a bounded logical decision; it is not a
signal aspect or permission for a real train to move.
